# Repo Tooling Standardization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `daniel-salvado-website` in line with the org-wide repo standard: full script surface (lint, format, format:check, typecheck, check, unit tests), lefthook-based pre-commit hooks, commitlint, a pinned Node version via `.nvmrc`, the latest pnpm pinned in `packageManager`, and a PR-validation GitHub Actions workflow.

**Architecture:** No application code changes. This is entirely tooling/config: `package.json` scripts and deps, a new `lefthook.yml` replacing `simple-git-hooks`, a new Vitest setup (jsdom + Testing Library) with one example test, a new `.github/workflows/ci.yml`, and doc updates to `README.md` / `CLAUDE.md`.

**Tech Stack:** pnpm 11.17.0, Node 22.18.0 (via `.nvmrc`), Vitest 4 + `@testing-library/svelte` 5 + jsdom, lefthook 2.1.10, existing ESLint/Prettier/svelte-check/commitlint setup, GitHub Actions.

## Global Constraints

- Package manager: pnpm, version pinned via `packageManager` in `package.json` — latest is `11.17.0` (current: `11.9.0`).
- Node version pinned via `.nvmrc` (not `.node-version` — per decision below, `.node-version` is removed).
- Node version value: `22.18.0` (matches current `.node-version`; do not change the actual version, only the pinning mechanism).
- Commit messages: Conventional Commits, enforced by commitlint via a lefthook `commit-msg` hook (config already at `.commitlintrc.json`, unchanged).
- Decision (confirmed by user): **no e2e tests** — this is a single-page, mostly-static personal site with no critical multi-step user flows; Vitest unit/component tests are the right level of coverage. Do not add Playwright.
- Decision (confirmed by user): lefthook pre-commit runs lint-staged-style checks only (`eslint --fix` + `prettier --write` on staged files) — not the full `lint`/`check`/`test` suite. Full suite runs in CI.
- Decision (confirmed by user): `.nvmrc` replaces `.node-version` (delete the latter).
- All new/changed scripts must actually pass locally before the plan is considered done (`pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm check`, `pnpm test`, `pnpm build`).
- Follow existing repo conventions: tabs, single quotes, no trailing commas, printWidth 120 (`.prettierrc`), Conventional Commits for every commit in this plan.

```ts
import { cleanup, fireEvent, render, screen } from '@testing-library/svelte';
import { afterEach, beforeEach, describe, expect, it, vi } from 'vitest';
import ThemeToggle from './ThemeToggle.svelte';

beforeEach(() => {
	document.documentElement.classList.remove('dark');
	localStorage.clear();
	window.matchMedia = vi.fn().mockImplementation((query: string) => ({
		matches: false,
		media: query,
		onchange: null,
		addEventListener: vi.fn(),
		removeEventListener: vi.fn(),
		dispatchEvent: vi.fn()
	})) as unknown as typeof window.matchMedia;
});

afterEach(() => {
	cleanup();
});

describe('ThemeToggle', () => {
	it('defaults to light mode', () => {
		render(ThemeToggle);

		expect(screen.getByRole('button', { name: 'Switch to dark mode' })).toBeInTheDocument();
	});

	it('switches to dark mode on click and persists the choice', async () => {
		render(ThemeToggle);
		const button = screen.getByRole('button', { name: 'Switch to dark mode' });

		await fireEvent.click(button);

		expect(document.documentElement.classList.contains('dark')).toBe(true);
		expect(localStorage.getItem('theme')).toBe('dark');
		expect(screen.getByRole('button', { name: 'Switch to light mode' })).toBeInTheDocument();
	});

	it('switches back to light mode on a second click', async () => {
		render(ThemeToggle);
		const button = screen.getByRole('button', { name: 'Switch to dark mode' });

		await fireEvent.click(button);
		await fireEvent.click(screen.getByRole('button', { name: 'Switch to light mode' }));

		expect(document.documentElement.classList.contains('dark')).toBe(false);
		expect(localStorage.getItem('theme')).toBe('light');
	});
});
```

### Task 6: Add GitHub Actions PR validation workflow

**Files:**

- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create the workflow**

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    name: Lint, typecheck, test, build
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Lint
        run: pnpm lint

      - name: Format check
        run: pnpm format:check

      - name: Typecheck
        run: pnpm typecheck

      - name: Svelte check
        run: pnpm check

      - name: Unit tests
        run: pnpm test

      - name: Build
        run: pnpm build
```

`pnpm/action-setup@v4` reads the pinned version from `package.json`'s `packageManager` field automatically — no version needs hardcoding here, so Task 2's pnpm bump is the single source of truth.

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add GitHub Actions workflow to validate PRs"
```
